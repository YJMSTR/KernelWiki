## Motivation

The FlashMLA scheduling kernel can fail with `CUDA error: invalid argument` near its accepted shared-memory limit. Its guard permits up to 48 KiB of dynamic shared memory, but the kernel also declares static shared memory. Without explicit opt-in, the combined allocation can exceed the default launch allowance.

On GB300 (152 SMs), a standalone call with 2,211 rows succeeds, while 2,212 rows requests 49,108 dynamic bytes and fails. The existing guard permits up to 2,214 rows. This reproducer calls only the scheduling kernel, independently of request-window KV copying.

## Modifications

- Use the existing per-device initialization helper to opt the kernel into 48 KiB of dynamic shared memory before launch.
- Preserve the schedule algorithm and existing dynamic-memory bound.
- Add four boundary cases validating schedule entries and split offsets against independently calculated expectations.

## Accuracy Tests

All 41 scheduling tests passed locally on GB300: 37 existing tests and four boundary cases. Existing coverage compares metadata with FlashMLA and checks attention-output parity where applicable. Pre-commit passes.
