## Motivation

MiniMax-H3's video VAE decodes a request as overlapping spatial tiles over temporal windows and blends them back together. On `main`, base H3 runs one tile per ViT decoder forward at every quality level (only FastH3 stacked its tiles, through `stack_tiling`), and the output chain after the decoder (tile blend + crop + place, temporal window blend into the destination frames, RGB de-normalization + clamp) is a sequence of FP32 aten ops, each a full pass over the frames. On 4x RTX PRO 5000 the decode stage is 3.26 s of a 30 s five-step 768p t2va request.

This PR:

- decodes up to 64 equal-shaped tiles per decoder forward under `quality="lossless"` (the default) and `"high"` on CUDA. Batching changes the GEMM shapes and therefore the output at rounding level, so it belongs to the lossless tier like the existing fused QK RMSNorm+RoPE;
- replaces the temporal blend write and the de-normalization with JIT kernels that reproduce the eager arithmetic bit-exactly and verify that on first use, so they are not tied to a quality level and run at every level, `exact` included. The tile blend + crop + place stays eager: a kernel for it needs the tiles as one tensor, which neither
