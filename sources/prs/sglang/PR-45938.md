## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
- After every DeepGEMM prefill top-k, `DeepGEMMPrefillData.write_page_indices` turned the request-local selections into index-K pool slots with torch: an add, a clamp, an int64 gather, a compare, a `where` and an int32 copy into the output, each a full pass over the `[rows, topk]` selection.
- `flat_selection_slots` does the same mapping in one Triton kernel that reads each selection once and writes the int32 slot, or -1 for an unselected entry.

Output is bitwise identical to before.

Verification:
- The kernel's output matches the torch mapping bit for bit for one and many requests per batch and from 300 to 65536 rows, on B300 and GB300.
- A micro benchmark on V4.1-Flash shapes shows it several times faster than the torch mapping on B300 and GB300.
