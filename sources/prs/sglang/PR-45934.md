## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
- `fused_k_norm_rope_flashmla` normalizes, ropes and stores every token's 512-wide KV row into the paged FlashMLA cache. It ran one 256-thread block per token with 4-byte loads, a shared-memory reduction and a block barrier, far below the copy rate of the row on large prefill batches.
- For the V4.1 layouts (fp8, fp4, uniform fp8) and batches of at least 2048 tokens, a new kernel gives each token one warp: each lane loads 16 consecutive values with 16-byte loads, the sum of squares stays in registers, and the existing `store_row` writes the lane's 16 values.
- The sum of squares is added in the same order as the block-per-token kernel, and the RoPE and sum-of-squares fma are pinned in both kernels, so the written rows are bitwise equal to before. Smaller batches (decode, short prefill) and the V4 layout keep the block-per-token kernel.

Output is bitwise identical to before.

Verification:
- The cache bytes written by the new kernel match the block-per-token kernel bit for bit for fp8 and fp4 layouts, int32 and int64 positions, strided inputs and skipped rows, from 1 to 65536 tokens, on B300 and GB300.
