## Summary
Faster MiniMax-M3 sparse attention on Hopper: Triton decode and prefill kernels with tiled block pointers (Triton >= 3.9), fp16-widened decode for fp8 KV on the paged path, and a fused bf16-to-fp8 cast in the fused K/V/index store.

## Changes to existing code
- On Hopper with `fp8_e4m3` KV, the sparse index K cache is stored in fp8 (it was bf16 unless fp8 attention GEMMs were on). Other platforms keep the previous dtype.
- The fused K/V/index store also handles an unscaled bf16-to-fp8_e4m3 cast (CUDA only); other inputs use the separate stores as before.

## Verification
- Kernel tests on H200: `test_minimax_sparse_fp8_attn_gemm.py` 88 passed; the fused store cast is bit-exact against `x.float().clamp(-448, 448).to(torch.float8_e4m3fn)`.
- MiniMax-M3.1-Flash on 8xH200, H200 cookbook recipe plus `--kv-cache-dtype fp8_e4m3`, sgl-eval 0.1.3, this PR vs. fp16 widening disabled:

| | GSM8K (greedy, 2 runs) | AIME26 (avg@8) |
|---|---|---|
| this PR | 96.21 / 96.06 | 91.25 |
| widening off | 96.36 / 96.51 | 93.75 |

The between-arm per-question divergence and correctness flips are within the run-to-run noise of either arm.

Cut from #45925 (MiniMax-M3.1-Flash support) at 10e6
