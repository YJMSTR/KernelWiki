## Summary

Layout conversion can require repeated padding, transposes, repacking, and full-tensor copies. This PR converts directly into the destination with Triton kernels, accelerating Blackwell value/scale conversions and Hopper scale conversions while preserving padding, strides, and fallback behavior. Scale kernels use byte views to support FNUZ FP8 storage without requiring hardware arithmetic support for those formats. Ordinary FakeTensors retain the Torch fallback; explicit compile warmup captures the same conversion specializations used at runtime through shared state that does not initialize CUDA during import. Ragged inverse conversion zeros unused logical capacity, including when there are no slices.

All timings below clear L2 before **every sample** by writing zeros across a separate buffer: 1 GiB on GB300 (129.25 MiB L2), 512 MiB on H100 (50 MiB L2). CUDA-graph event pairs bracket only the conversion; cache clearing and CPU allocation/launch overhead are excluded. Results are the median of three trials of 32 samples each; API tables use preallocated output. Bandwidth counts required input + output bytes. `rhs` uses K-axis `-2`; `lhs` uses K-axis `-1`.
