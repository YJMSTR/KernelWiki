## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Gluon TMA operations currently cannot express L2 eviction hints, and descriptor-load rewrites discard their cache policy. Add the single `cache_policy` argument to `async_load`, `async_load_im2col`, `async_store`, `async_gather`, and `async_scatter`, including the Blackwell reexports.

All five APIs accept the existing generic or NVIDIA `CachePolicy` objects, including `CachePolicy(l2=FractionalEvictionPolicy(...))`. Omission or `None` emits no hint; explicit detailed `evict_normal` remains a real L2 policy. There is no separate `eviction_policy` argument on the TMA frontend. Share the L2-only validation across the Python APIs and TMA IR operations: reject L1 policies, cache modifiers, and prefetch sizes, while retaining the existing volatile-load rejection.

Use one optional `cachePolicy` IR attribute and the common decoder/policy generator. Emit the 64-bit policy operand on every message, after im2col offsets and the multicast mask where present. Keep existing no-policy C++ builder overloads.
