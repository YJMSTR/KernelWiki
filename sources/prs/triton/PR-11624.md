## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Fix by @Maratyszcza

E8M0 byte `0` represents `2^-127`, and byte `255` represents NaN. Several software decoders treated these as zero or infinity. Correct both encodings across compiler lowering, the interpreter, standalone upcasts, packed Hopper FP4 layouts, and scaled reductions. For example, a 128-term dot product of BF16 `2^112` and FP8 `256` with scale byte `0` must return `1`; the old decoder returns `0`.

The fix covers integer E8M0 scales with FP4 E2M1 and FP8 E4M3/E5M2 values. Scaled reductions also cover BF16 and FP32 inputs. BF16 and FP32 decoding preserve the minimum value; FP16 still rounds it to zero. H100 software decomposition is affected, including two-scaled FP8 matmuls. Native NVIDIA block-scaled MMA keeps its existing path, and a zero floating-point scale remains zero.

Numeric software decoders zero-extend and shift the scale byte, preserve the BF16/FP32 minimum with an integer maximum, and use `fma(scale, +0, scale)` to turn the infinity encoding into NaN. The generic FP16 path omits the minimum correction because that value rounds to zero. The FMA precedes FP16 narrowing; generic dot decomposition also decodes before scale broadcasting.
