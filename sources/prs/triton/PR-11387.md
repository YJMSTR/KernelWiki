## Summary

Follow-up to [Reduce MXFP4 layout conversion allocations](https://github.com/triton-lang/triton/pull/11360).

Write CUDA FP4 values directly from Hopper or Blackwell storage into the requested `StridedLayout(-1)` or `StridedLayout(-2)` output, eliminating the full-sized canonical intermediate.

- Hopper: fuse decoding, inverse tile permutation, and nibble repacking.
- Blackwell: reuse the existing repacker for the default layout and extend the existing shuffled converter to write either packing axis.

Both use the same layout-level dispatch and destination shape/stride metadata. The public API and forward conversion behavior are unchanged. Other conversions retain the canonical fallback; empty public conversions preserve output metadata and skip only the kernel launch.

## Performance

Synthetic logical shape `[16, 4096, 4096]`, 128 MiB packed input; four balanced rounds of 25 synchronized warm public `convert_layout` calls. Both platforms use a compiler built from [the main revision](https://github.com/triton-lang/triton/commit/d3554fba526442d878c2eae2bb57cfc3c59eacf6). Inputs and expected outputs come from the respective baseline's CPU conversion.
