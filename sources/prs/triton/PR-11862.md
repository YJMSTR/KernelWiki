## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Fixes #11859.

`has_tma_gather()` is `cuda_capability_geq(10, 0)`, which is also true on consumer Blackwell (12.x), and `matmul.py` uses it for both `has_gather_tma` and `has_scatter_tma`. sm_12x has TMA gather but no scatter (#11344, and `test_tma_scatter` is skipped for `is_sm12x()`), so a matmul with a scatter index and a persistent output failed in ptxas with `Feature '.tile::scatter4' not supported on .target 'sm_120a'`.

This adds `has_tma_scatter()`, false on 12.x, and uses it for `has_scatter_tma`, so those cards take the non-TMA scatter that Hopper already takes. Gather is unchanged.

On an RTX PRO 6000 (sm_120) with `main` bde7dafd6, of the 288 `test_matmul.py::test_op` cases that failed this way 280 pass; the other 8 are #11860 and pass with #11861 on top. With both, what still fails in `triton_kernels/tests` on that card is the 99 KB shared memory limit (`OutOfResources`).
<!-- upstream-excerpt-end -->
