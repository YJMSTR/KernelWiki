## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Single-slice matmuls currently launch a second kernel to build a schedule that can be written during metadata initialization. Converting an already encoded activation-scale tensor to a different Blackwell activation-scale layout also decodes it to a temporary strided tensor before re-encoding it.

This PR removes those two setup costs:

- Populate a single-slice schedule in the existing initialization kernel. Multi-slice scheduling keeps its existing implementation.
- Read encoded source scales directly in the existing conversion kernel for non-gradient 2D byte scales with a batched or single-slice source. Caller-provided output buffers, multi-slice sources, and other unsupported combinations retain the existing path.

Both changes are shared GEMM infrastructure, applicable to prefill and decode callers. They do not change model arithmetic or select a serving configuration.
