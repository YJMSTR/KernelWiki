## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Blackwell FP4 conversion had a separate column-major stride algorithm, and the shuffled-layout converter imported it to allocate plain-layout output. Make physical strides part of `BlackwellMXValueLayoutTransformation` and derive them through the existing `StridedLayout` implementation. All three allocation sites now use layout-owned metadata, removing the duplicate algorithm and keeping the physical layout definition in one place.

The two direct-conversion calls use `major_dim=-2`, which the shared converter already normalizes. GPU kernels, packing, padding semantics, and output allocation sizes are unchanged. This follows [Convert between Blackwell FP4 layouts directly](https://github.com/triton-lang/triton/pull/11563).

Move the Blackwell-specific conversion and allocation tests beside the existing Blackwell tests. Keep all 96 CUDA conversion cases, including empty inputs and supplied output buffers, while reducing repeated CPU/meta fallback cases from 192 to 32. Check output device, default plain-layout strides, and shuffled contiguity; value equality alone would miss an incorrectly ordered allocation.
