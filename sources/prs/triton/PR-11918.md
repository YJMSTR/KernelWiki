## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
On a Jetson Thor (SM110), Gluon tests requesting a 16-CTA cluster fail at launch with `CUDA_ERROR_INVALID_CLUSTER_SIZE` / "cluster misconfiguration". For example, pytest's `ctas_per_cga2` label is the `[4, 4]` parameter, which requests 16 CTAs rather than 2.

Query cluster occupancy once per device and requested size using a small Triton kernel, then skip affected test parameters when even that low-resource kernel cannot fit a cluster. The probe is only a test prefilter: a real kernel can still have stricter resource limits. Existing 2/4/8-CTA cases continue to run.

Reproduce on a Thor GPU before this change:

```bash
CUDA_LAUNCH_BLOCKING=1 python -m pytest -s --tb=short -q -n 0 \
  'python/test/gluon/test_core.py::test_shared_gather_cga[16-cta-sharded]' \
  --device=cuda
```

Before: `RuntimeError: Triton Error [CUDA]: a kernel launch error has occurred due to cluster misconfiguration`. After: skipped with `Device does not support 16 CTAs per cluster`.
