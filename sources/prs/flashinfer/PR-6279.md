## 📌 Description

Build FlashInfer's `moe_utils` kernels for every grouped_mm architecture (SM80–SM121) and use them in the cuDNN grouped-GEMM unified MoE backends.

- The four cuDNN runners use `moe_sort` / `moe_permute` / `moe_activation` / `moe_unpermute` on every architecture, replacing the torch routing, permute and finalize fallback and Triton's `silu_and_mul`.
- Activations: `SwiGLU` (default scalars), `GeGLU`, `GELU`, `ReLU`, `SiLU`, `Identity` (previously `SwiGLU` only).
- `moe_activation`: grid-stride over (row, 16-byte copy) items with a work-sized launch; the binding takes the caller's CUDA stream for CUDA graph capture.
- `moe_sort`: before SM90 (no cluster or cooperative routing kernel), the expert-counts buffer is allocated above 4 tokens.
- FP8 per-tensor: the BF16 intermediate is requantized to E4M3 with torch ops before GEMM2.

Behavior changes:
- `prepare_cudnn_grouped_gemm_*_weights` keeps gated fc1 rows in the canonical `[up, gate]` order (was `[gate, up]`); weight views prepared by an earlier build must be prepared again.
