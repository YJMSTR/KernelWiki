## 📌 Description

The persistent Kimi-K3 AttnRes programs in `flashinfer/experimental/cake_kimi_k3_attn_res` are the 288-thread schedules whose consumer warps park FP32 partials in TMEM. Their consumer warps read TMEM with `tcgen05.ld` and use the result registers directly. After the token loop, all 288 threads meet at `barrier.sync 9, 288`, and consumer warp 0 then runs `tcgen05.dealloc`. No `tcgen05.wait::ld` exists anywhere in these programs.

A true register dependency on a `tcgen05.ld` result orders only the register value. The PTX ISA (tcgen05 memory consistency model, "Register dependencies, same thread") states that such a dependency "does not imply any other form of ordering ... To enforce such memory orderings and avoiding anti-dependency hazards around `tcgen05.ld`, `tcgen05.wait::ld` must be used." `tcgen05.wait::ld` is the completion mechanism of `tcgen05.ld`. Without it, the TMEM columns can be deallocated while a load from them has not completed.
