## 📌 Description

The two native Kimi-K3 AttnRes programs in `flashinfer/experimental/cake_kimi_k3_attn_res` have the same missing drain that #6740 fixes in the persistent programs:

* `cake_kimi_k3_attn_res_99f148a06e530e457f4a` (route key `native_k8`);
* `cake_kimi_k3_attn_res_709f669fe8647d61aaf0` (route key `native_m128`).

Both are built for SM100 and SM103.

Their consumer warps read TMEM with `tcgen05.ld` and use the result registers directly. After the token loop, all 288 threads meet at `barrier.sync 0, 288`, and warp 0 then runs `tcgen05.dealloc`. No `tcgen05.wait::ld` exists anywhere in these programs.

A true register dependency on a `tcgen05.ld` result orders only the register value. The PTX ISA (tcgen05 memory consistency model, "Register dependencies, same thread") says such a dependency "does not imply any other form of ordering ... To enforce such memory orderings and avoiding anti-dependency hazards around `tcgen05.ld`, `tcgen05.wait::ld` must be used." Without the wait, the TMEM columns can be deallocated while a load from them is still in flight.
