## 📌 Description

Add the Cake FMHA route `decode_native_bf16_hd256_smallm_v1` to the `cake_fmha` package: BF16 Q/KV/O paged GQA decode with head_dim 256 and 17..64 packed (speculative token × head) rows per KV head in a 32- or 64-row tile (rows above the packed count are padding; the Q tensor-map box always fills the tile), selected through the existing `backend="cake"` entry points (`trtllm_batch_decode_with_kv_cache`, `cake_batch_decode_with_kv_cache`).  Target workload: Qwen3.5-35B-A3B on 2× B200 with TP=2, batch 1, ISL 60k, 7 draft tokens — per rank 8 query rows × 8 heads over one KV head.  Before this change that shape had no optimized Cake route and ran on `cake_fmha_compat_v1`.
