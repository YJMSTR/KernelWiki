## Summary

Re-exports the SM100 / SM103 DeepSeek-V4 NVFP4 sparse-MLA decode family (`backend="cake"`, `kv_cache_format="nvfp4"`)
with one kernel change in the **persistent member** (`nvfp4_decode_persistent`, the member that serves the 128-head
throughput rows): the next tile's V transform now runs under the current tile's PV MMAs. The member set, the host route,
the loader registrations and the public API are unchanged; the other members' generated sources are regenerated from the
same exporter and are byte-identical to the previous delivery except for the regenerated receipts.

- **What changes in the kernel.** The persistent member's shared memory was full (230944 B of 232448 B), so the compute
  warps could not start transforming the next tile's V (E2M1 x E4M3 -> E4M3, MN-major) until the MMA warp had finished
  reading the single V buffer; the transform sat exposed between PV(t) and QK(t+1) on every tile. The Q NoPE E2M1 tile is
  written once and read by every tile, and the tensor core can take it from TMEM: the kernel now stores the Q codes into
  64 free TMEM columns and issues QK as `tcgen05.mma.kind::mxf4nvf4` with the A operand from TMEM (same K-set order, same
