## 📌 Description

Adds an SM107 (Rubin) backend for `gemm_fp8_nt_groupwise`, the FP8 GEMM with 1x128 activation scales and 128x128 weight scales. It is built on the public CUTLASS 4.8 CuTe-DSL `SM107BlockwiseGemmKernel`. **No default changes:** the new `backend="cute-dsl"` and `backend="auto"` are opt-in, and the default stays `"cutlass"`.

**Problem.** On Rubin the only backend for this API is CUTLASS, built for `sm_100f` rather than natively for SM107. Its kernel uses fixed 128x128 output tiles and never splits K. For large weights, the tile count fills Rubin's SMs badly: either most SMs sit idle, or a mostly empty last wave costs a full K loop.

**What this adds.**
- `flashinfer/gemm/kernels/blockwise_gemm_rubin.py` and `blockwise_gemm_blackwell.py`: the vendored public CUTLASS 4.8 kernel classes (NVIDIA/cutlass@0b55a2f6, `examples/python/CuTeDSL/cute/{rubin,blackwell}/kernel/blockwise_gemm/blockwise_gemm.py`). The Rubin class subclasses the Blackwell one. The example's tensor setup, command-line and benchmark code was removed; kernel logic is unchanged.
