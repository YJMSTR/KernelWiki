## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
This PR adds the Cake backend `cake_tinygemm2_tcgen05`, which contains generated tcgen05 programs for `flashinfer.gemm.tinygemm_bf16` (BF16 `out = input @ weight.T (+ bias)` for small batches). It covers every variant: BF16 with and without bias, with and without PDL, using narrow, packed and per-chain-accumulator tiles. That makes 12 programs per architecture for sm_100a, sm_103a and sm_107a. A shape uses these programs only inside per-architecture windows where they measured faster. Other shapes keep their current kernel. The baseline is what the op runs today: Cake `tinygemm2_sm100` with a bias and FlashInfer `tinygemm2` without one. The tables below show the speedups.

Times are CUPTI kernel times in µs (median, cold L2) with PDL off. Speedups marked † fall outside the routing windows and keep their current kernel, so both columns time the same kernel.

**NVIDIA B200** (sm_100a, 148 SMs), CUDA 13.4, PyTorch 2.14.1+cu130
