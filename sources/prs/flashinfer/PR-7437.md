## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
`flashinfer.diffusion_ops.cake_minimax_h3_sm120_quant_out_proj` computes the MiniMax-H3 out-projection on SM120 (`sm_120a`) in two variants: FP8 per-token (`minimax_h3_fp8_out_proj`) and NVFP4 (`minimax_h3_nvfp4_out_proj`). Each variant runs as one persistent launch that does the activation quantization, the GEMM and the gate/residual epilogue. Each quantization has two programs. The warp-epilogue program runs on the 188-SM RTX PRO 6000 Blackwell. The CTA-epilogue program runs on every other `sm_120a` device, such as the RTX 5090. This PR changes only the CTA-epilogue programs. Every MMA lane now issues `fence.proxy.async.shared::cta` after its `ldmatrix` / `ld.shared` reads of a shared-memory ring stage and before the warp releases that stage to the TMA producer. The fence is needed because the TMA refill is an async-proxy write, and the release arrive alone does not order the earlier generic-proxy reads before that write. The warp-epilogue programs already had this fence. The host code and the arithmetic are unchanged, and the output is bitwise equal. This fixes ordering and is not meant to speed anything up.
