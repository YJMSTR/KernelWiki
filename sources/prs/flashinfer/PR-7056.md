## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
The Cake QSA kernel (`flashinfer.experimental.cake_qsa_nvfp4`, called as `flashinfer.sparse.qsa_sparse_paged_attention(..., backend="cake")`) does NVFP4 sparse paged GQA decode attention. It takes BF16 queries and writes BF16 outputs, reads an NVFP4 (E2M1) paged KV cache with E4M3 block scales, and accumulates in FP32. The kernel has one data type, two KV layouts (NHD, HND) and two forms, for four variants in total, and this PR delivers all four. The fused form is a single cooperative launch whose split-KV merge is done by the splits' own CTAs. The split form runs a decode kernel followed by a separate merge kernel, and the host picks the form for each call. Against the existing `flashinfer.sparse.qsa_sparse_paged_attention` default backend, given the same inputs through the same public call, it is 1.33x-1.83x faster across 16 shapes, or 1.35x-1.90x when L2 is flushed by a read sweep instead.
