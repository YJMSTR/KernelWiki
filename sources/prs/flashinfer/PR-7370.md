## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
This PR speeds up the narrow tile of `cake_tinygemm2_tcgen05`. That is the Cake backend that #7302 added for `flashinfer.gemm.tinygemm_bf16` (BF16 `out = input @ weight.T (+ bias)` for small batches), and it contains generated tcgen05 programs. The backend supports BF16 only, with and without bias and with and without PDL. It has three tiles: narrow, packed and per-chain-accumulator. In this PR, the narrow tile unrolls its MMA and loader loops in blocks of rounds, and it comes in three builds. Each architecture sends its narrow windows to its fastest build. On sm_100a, that is the build unrolled by two rounds. On sm_103a, it is the build unrolled by four MMA rounds that issues full stages without a per-step K test. On sm_107a, it is the build unrolled by four MMA rounds. The narrow windows were re-measured on each architecture, so more shapes now use the narrow tile. Each architecture now has 20 programs instead of 12. The packed and accumulator tiles keep their code, and the four packed programs are renamed. Shapes outside the windows keep their current kernel. The baseline is what `tinygemm_bf16` runs on FlashInfer main today: the round-1 Cake programs and windows from #7302.
