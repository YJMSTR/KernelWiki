## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
This Cake attention kernel family has three variants. All three do dense non-causal MHA with D = 128, take BF16 in, give BF16 out and use FP32 softmax. They accept any strides (NHD or HND views). Each variant is one call that runs a chain of statistics, quantization and attention kernels. Two variants, NVFP4 QK + NVFP4 PV on SM100 / SM103 and INT8 QK + NVFP4 PV on SM120, are in `flashinfer/experimental/nvfp4_attention`. The third, INT8 QK + FP8 E4M3 PV on SM90, is in `flashinfer/experimental/cake_fp8_attention`. This PR changes only the SM120 attention kernel of the already shipped `flashinfer/experimental/nvfp4_attention` package. The API stays the same, `flashinfer.prefill.prepare_nvfp4_attention(q, k, v, out, backend="cake")` and `nvfp4_attention_workspace_bytes`, and the SM100 / SM103 kernels are unchanged. The change is a correctness fix that adds the required asynchronous-proxy fences between the kernel's shared-memory writes and the TMA reads that follow them. The fix costs a little time. We measured the complete BF16-in / BF16-out call under CUDA-graph replay against the previous Cake version, currently on FlashInfer main. Both sides ran the same script in the same session
<!-- upstream-excerpt-end -->
