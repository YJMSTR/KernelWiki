## 📌 Description

FA2 tensor-core decode now takes an e4m3 query over an e4m3 KV cache. Q·Kᵀ and P·V both run on m16n8k32 e4m3 MMA, so no K or V element is converted to bf16. The softmax uses the VO-split layout, here from head_dim_vo 256: each KV warp stages its probabilities in shared memory as e4m3 words (P × 256) and multiplies the whole 64-token tile into its own 64-dim output slice. A thread then keeps 32 output accumulators instead of 128, and no cross-warp output merge is needed. The denominator stays the fp32 cross-warp sum. The query scale reaches the kernel the existing way, `run(q_scale=...)` folded into `sm_scale`.

The query dtype is part of the JIT module key, so bf16 and fp16 query modules do not change; their SASS matches the merge base. The ragged kernel is not instantiated for an e4m3 query.

`plan()` accepts an e4m3 query only where it was validated: SM120, single-token decode, e4m3 KV cache, bf16 output, head_dim 256, no RoPE or soft cap, and 1, 2, 4 or 8 query heads per KV head. Anything else raises `NotImplementedError`, and `fast_decode_plan()` rejects multi-token requests for this query.
