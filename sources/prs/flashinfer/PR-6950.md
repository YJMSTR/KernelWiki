## 📌 Description

The Rubin (SM107) CuTe DSL fused-MoE finalize grouped GEMM only implemented the fused atomic scatter-add, so `cute_dsl_fused_moe(..., use_fused_finalize=False)` raised `NotImplementedError` on SM107. SGLang now defaults to the unfused finalize (sgl-project/sglang#40105) and its `--enable-deterministic-inference` mode forces it, so the `flashinfer_cutedsl` MoE runner failed at autotune warmup on every rank on Rubin (Qwen3.5 NVFP4, 2x Vera Rubin NVL72).

This adds the unfused path to the SM107 finalize kernel, mirroring the Blackwell kernel:

- `Sm107BlockScaledContiguousGroupedGemmFinalizeFusionKernel` takes `use_fused_finalize` (default `True`). When `False`, the epilogue writes each unscaled permuted row to its expanded `(token, top-k slot)` row with a `cp.async.bulk` store instead of the bf16 atomic reduce into the token row, and the output tensor is sized `num_tokens * top_k`. The fused path is unchanged.
- The dispatcher passes the flag through instead of raising. The caller already allocates the expanded output and runs the fixed-order `moe_unpermute` reduction for any arch, so the deterministic contract of #3976 now holds on SM107.
