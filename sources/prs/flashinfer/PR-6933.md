## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
`flashinfer.mla.nvfp4_sparse_mla_decode` runs sparse MLA decode over an NVFP4 (`nvfp4_ds_mla`) KV cache. It takes E4M3 queries `[T, 16, 576]`, 352-byte NVFP4 cache rows and int32 top-k row indices `[T, topk]` (-1 = empty slot), and it writes BF16 output `[T, 16, 512]`. Each query token gets one thread-block cluster of C CTAs (grid (T, C, 1), 448 threads per CTA, 32-key stages, up to 2048 keys per CTA). The CTAs in a cluster merge their fp32 partials through distributed shared memory, and C = 1 writes its output directly. The public API has two backends: `backend="cuda"` is the hand-written kernel and `backend="cake"` runs the generated programs. This PR delivers the Cake backend's seven programs, one for each cluster size C in {1, 2, 3, 4, 5, 6, 8}, as a build-manifest package, and the host planner picks C for each launch from the device's live cluster capacity. The baseline is the previous Cake version of the same seven programs as shipped before this PR, measured on the same input shapes in the same interleaved runs.
