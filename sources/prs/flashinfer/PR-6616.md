## 📌 Description

FlashMLA's DeepSeek-V4.1 ABI (as of its 2026.09.30 release) stores each token as one self-contained record: each token's data is followed by its own scales. vLLM adopted it in vllm-project/vllm#61371. The SM120 sparse-MLA DSv4.1 path reads only footer-scale pages, in which a page holds all its tokens' data and then all their scales.

The two layouts have the same record size (528 B), so a cache in the other layout passes every shape check and decodes into silently wrong output. This PR adds the inline-scale records as new, explicit formats. The existing names keep their footer meaning.

| | main (SWA) cache | FP4 compressed cache |
|---|---|---|
| Footer (`fp8_dsv41`, `ue8m0_g32`) | per page: P × 512 B E4M3, then P × 16 B UE8M0 | per page: P × 256 B E2M1, then P × 32 B E4M3 |
| Inline (new) | per token: 512 B E4M3 + 16 B UE8M0 (group 32) = 528 B | per token: 256 B E2M1 + 32 B E4M3 (group 16) = 288 B |

As in FlashMLA, sparse indices address inline records as rows of the whole cache, and a page stride must be a whole number of rows.
