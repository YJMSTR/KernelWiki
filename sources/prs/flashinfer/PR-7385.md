## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
This PR speeds up `cake_nvfp4_mla_decode` (`flashinfer.mla.prepare_nvfp4_batch_decode_with_kv_cache_mla`, experimental), the MLA decode with NVFP4 queries and KV cache. The kernel has one variant, and this PR changes it. On SM100 only, it adds a decode program that issues the QK MMAs two KV tiles ahead of PV. The host picks this program for balanced plans whose work units are all long. On both architectures, it replaces the split-KV combine with a faster build. The baseline is the previous Cake version in `main`. Speedup is `main` latency divided by this PR's latency, using the median of one complete call.

On B200, the rows that use the new decode program reach 1.039x (64K keys), 1.055x (128K keys) and 1.029x (52224 keys). The two small split shapes reach 1.025x and 1.024x. On GB300, the same two shapes reach 1.016x and 1.026x, and 8K keys reaches 1.006x. All other rows are within measurement noise of `main`.

**NVIDIA GB300 (sm_103a), CUDA 13.4**

| Shape | `main` (µs) | This PR (µs) | Speedup |
|---|---:|---:|---:|
| 2 requests (256, 300 keys), 64 heads, 6 query tokens, forced 2-way split | 11.97 | 11.78 | 1.016x |
| 3 requests (1000, 8192, 5000 keys), 8 heads, 6 query tokens |
