## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
`cake_warp_decode` is Cake's NVFP4 routed fused-MoE decode for 1 to 32 tokens, called through `flashinfer.fused_moe.trtllm_fp4_block_scale_routed_moe(...)` with `CakeWarpDecodeConfig(backend="cake")`. It has one data type (NVFP4 W4A4, BF16 output), five activation variants and one fused form: FC1 with the activation, FC2 and the top-k finalize. This PR changes only the host-side schedule selection. It moves 75 rows on sm_100a and 26 on sm_103a to schedules the module already ships, and outputs are unchanged. Against the previous Cake selection on FlashInfer main, the rerouted rows run up to 1.29x faster on sm_100a and up to 1.24x faster on sm_103a.

The "memset" and "read" column groups are two cold-L2 modes: before every call, we flush L2 with a memset of a large buffer or a read of one.

**sm_100a** (NVIDIA GB200, CUDA 13.4). Latency in us of one routed-MoE call (FC1, FC2, finalize), cold L2; previous = the current Cake selection, new = this PR; ratio = new / previous. **Bold** num_tokens = rows this PR routes to a different schedule.

`e512_i512_k10`: hidden 2048, intermediate 512, 512 experts, top-10, swiglu
