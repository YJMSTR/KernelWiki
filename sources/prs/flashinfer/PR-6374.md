## 📌 Description

On Rubin (SM107), the CuTe DSL NVFP4 MoE rejected any non-default `swiglu_alpha` / `swiglu_beta` / `swiglu_limit` with `NotImplementedError`. As a result, clamped-SwiGLU models such as GLM-5.3 (plain SiLU-and-mul with only `swiglu_limit` set) could not use this backend on SM107.

This PR ports the SM107 SwiGLU clamp from TensorRT-LLM (NVIDIA/TensorRT-LLM#19488) to FlashInfer's copy of the same Rubin kernel (`rubin/blockscaled_contiguous_gather_grouped_gemm_swiglu_fusion.py`):

- **Kernel:** adds a trace-time `swiglu_limit` constant. When it is finite, the alpha-scaled gate is capped at `+limit` and the alpha-scaled up branch is clipped to `[-limit, limit]` (`min.NaN.xorsign.abs.f32`) before the activation, in both the vectorized and scalar epilogues. This matches the existing Blackwell kernel. A limit of `+inf` emits no clamp code.
- **Dispatcher (`blockscaled_contiguous_gather_grouped_gemm_act_fusion.py`):**
  - Only custom `swiglu_alpha` / `swiglu_beta` are still rejected on SM107.
  - `DEFAULT_SWIGLU_LIMIT` (fp32 max) is mapped to `+inf`, so unclamped kernels are unchanged.
  - A finite limit is accepted for plain SwiG
