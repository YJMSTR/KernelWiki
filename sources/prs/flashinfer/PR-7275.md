## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Cake ships one mHC (manifold-constrained hyper-connections) with-grad variant in FlashInfer as `flashinfer.cake_mhc_train`: four residual streams at hidden size 4096, a run-time token count T, BF16 activations at the API boundaries, the mapping GEMM, the Sinkhorn coefficients and the parameter gradients in FP32, with forward, gradient and checkpoint paths. This PR changes only which column-slab program the gradient entry point `cake_mhc_train_backward_finish` launches on SM100 and SM103: at T ≤ 4096 tokens on SM103 and at 4096 < T ≤ 8192 tokens on SM100 it now launches a dynamic-schedule form of the same kernel, so the gradient pass keeps its speed while another kernel, such as a communication kernel, holds SMs; the arithmetic, outputs, public API, workspace layout and saved statistics are unchanged, and every other token count, every other program and SM107 keep the previous programs. The baseline is the previous Cake version of the package (the static schedule merged in #7198), timed as kernel time per call in the same process on the same inputs and GPU: with 16 CTAs x 640 threads of a side kernel resident, the ratio this PR / previous is 0.7776–0.7798 at T = 4096 on GB300 and 0.
<!-- upstream-excerpt-end -->
