## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
`flashinfer.experimental.cake_stepfun_moe` ships the StepFun SwiGLU-Step routed MoE in five precision families (BF16, per-tensor FP8, MXFP8, NVFP4 and per-token NVFP4) on sm_100a and sm_103a, each with FC1 programs for several token tiles. This PR changes one program: the MXFP8 tile-256 FC1 kernel (`cake_stepfun_moe_c16c727913eac39c7f25`), on both architectures.

It fixes a memory-ordering bug. The kernel's scale-factor loader fills the B scale factors in shared memory with `cp.async`, which writes through the generic proxy. The leader CTA then copies them into tensor memory with `tcgen05.cp`, which reads shared memory through the async proxy. The PTX ISA (tcgen05 memory consistency model, "Shared Memory Accesses") requires a `fence.proxy.async` between generic-proxy writes to shared memory and a `tcgen05.cp` that reads them. The loader had no such fence between its `cp.async.wait_group` and the mbarrier arrival that publishes the stage to the leader. This PR adds `fence.proxy.async.shared::cta` after each `cp.async.wait_group` (the in-loop `wait_group 1` and the tail `wait_group 0`) and updates the unit's two `build.json` digests. No other program changes.
