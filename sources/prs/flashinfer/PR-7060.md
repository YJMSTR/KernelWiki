## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
This PR adds 8 aligned program variants to the head-dim-128 single-query paged GQA decode of the `cake_fmha` module (`trtllm_batch_decode_with_kv_cache(backend="cake")`). The variants use cluster sizes of 8 / 4 / 2 / 1 CTAs per (request, KV head), each built for a BF16 and an FP16 KV cache, and a host-side band selector over (batch x KV heads, max KV length) picks one per launch in front of the module's present routes. All 8 variants ship for sm_100a and sm_103a (the same programs, compiled per target). The speedup baseline is the module's previous Cake route for each shape (`decode_native_bf16` for BF16, `decode_balanced_fp16` for FP16), and both sides are measured through the same public entry point. The tables below have one row per shape of the measured shape list, with both latencies beside each ratio, and rows marked `unchanged` keep the previous route.

### NVIDIA B200 (sm_100a)

NVIDIA B200 (sm_100a, CUDA 13.0); median kernel time in us with the L2 cache flushed before every launch; speedup = previous / this PR. Rows whose route is unchanged run the same kernel on both sides; their two latencies are the medians of the same kernel timed first in 3 fresh processes on each sid
