## 📌 Description

`computeCtaAndClusterConfig` sets the KV split count to `SMs / (batch × headsKv × …)`, rounded down. When that base CTA count is close to the SM count, the split count drops to 2 or 1. Then two things happen:

- One request with long KV sets the kernel time, because each CTA walks its whole KV.
- At 2 splits, the grid can be one full wave plus a few CTAs.

This PR adds an opt-in rule. If `FLASHINFER_TRTLLM_GEN_MULTI_WAVE_KV_SPLIT=1` and one wave gives 2 splits or fewer, the split count is computed for up to 4 waves of CTAs. The default is unchanged.

- **Scope:** GQA generation kernels only. MLA is excluded.
- **Final config only:** the tile search keeps the default rule. Only the selected kernel gets the new split count.
- **Wave cap:** `kMaxNumWavesForKvSplit = 4`, with a `static_assert`. More than 4 waves can give a zero-size grid for the separate reduction kernel (`fmhaReduction.cu`).
