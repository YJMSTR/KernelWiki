## 📌 Description

At decode batch sizes the trtllm-gen MoE finalize step (`finalize::run`, non-DeepSeek path) uses `finalizeKernel`, where each thread reads one scalar element per expert and walks the topK dependent index/data loads serially. For high top-k models this is a large share of a MoE call's fixed cost at one token.

This adds `finalizeKernelSmallBatch` for the same regime (`ceil(hidden/256) * numTokens < 1184`, 128-bit aligned hidden, `4 < topK <= 64`):
- one CTA per (token, hidden slice), 128-bit loads;
- the topK reduction is split across `blockDim.y` thread groups so each thread issues at most four independent loads, and partial sums are combined through shared memory;
- the routing permutation and expert weights are read before `cudaGridDependencySynchronize()` (they come from routing, which has completed before the GEMMs this kernel depends on can start, as `finalizeKernelVecLoad` already assumes); only the GEMM output is read after the wait;
- programmatic launch completion is triggered at kernel start, so the next kernel can launch while finalize runs.
