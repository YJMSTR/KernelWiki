## 📌 Description

Enable GQA token/head grouping for multi-token TRT-LLM generation attention with NVFP4 KV cache.

Previously, NVFP4 K/V with FP8 queries failed the grouping eligibility check and used ungrouped kernels. Recognize E2M1 K/V independently of query/output dtype and workload shape so the existing grouped kernel selector can handle multi-token decode.

Single-token NVFP4 decode retains its existing ungrouped dispatch. Non-NVFP4 eligibility and the separate MLA/context selectors are unchanged.

### Performance

Grouping-enabled decode substantially reduces multi-token NVFP4 kernel latency across the measured request batches and MTP lengths. Single-token decode retains the ungrouped path and shows similar latency.

![NVFP4 decode performance comparison](https://github.com/user-attachments/assets/398a14b3-456a-4067-b0a8-0008b8f125e0)

Measured on NVIDIA GB200, CUDA 13.0, and PyTorch 2.13.0 using `trtllm_batch_decode_with_kv_cache`: FP8 E4M3 queries/output, NVFP4 K/V, HND layout, 32 query heads, 2 KV heads, head dimension 128, and a 65,536-token context.
