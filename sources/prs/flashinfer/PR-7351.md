## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
The Cake backend of `flashinfer.gemm.bmm_bf16` has one input type (BF16), one layout and three output types (BF16, FP16, FP32). Until now every shape ran on hand-written mma.sync kernels. This PR adds a tcgen05 swap-AB variant: weight rows fill the MMA's M, decode tokens fill N, split-K across a cluster is optional, and the FP32 accumulator is rounded once to the output type. The host routes 9 decode shapes per architecture to it (K = 1024, M = 8-33, batch 1-4, all three output types), which run 1.01x-1.20x faster on B200 and 1.03x-1.22x faster on GB300 than the previous Cake kernel (the same `backend="cake"` call on the mma.sync kernels).

NVIDIA B200 (sm_100a, CUDA 13.4, driver 580.82.07): GPU kernel time per call (CUPTI, cold L2), mean of two sessions' medians over 7 interleaved rounds, speedup = previous / this PR. "unchanged" rows run the same kernel in both columns, so their 0.99x-1.01x ratios are measurement spread; "bf16, 2 calls" times two back-to-back calls as one span.

| batch | M | N | K | output | kernel | previous (µs) | this PR (µs) | speedup |
|---:|---:|---:|---:|---|---|---:|---:|---:|
| 5 | 17 | 24 | 256 | bf16 | unchanged | 2.35 | 2.35 | 1.00x |
| 4 | 128 | 256
