## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
This PR speeds up `cake_nvfp4_mla_decode` (`flashinfer.mla.prepare_nvfp4_batch_decode_with_kv_cache_mla`, experimental), the MLA decode with NVFP4 queries and KV cache. The kernel has one variant. This PR adds two programs to it on SM100 and SM103. A decode program for short work units is picked when every unit holds at most 4096 KV tokens on SM100 or 8192 on SM103. On SM100, the existing QK-ahead program still takes priority. A new combine program is used when some row has three or more KV splits. Plans with at most two splits per row keep the existing combine. The existing programs are unchanged. The baseline is the previous version of this kernel in `main`. Speedup is `main` latency divided by this PR's latency. Each latency is the median of one complete call.

On GB300, 2 requests reach 1.109x with a forced 3-way split and 1.066x with a forced 2-way split. 3 requests with 8 heads reach 1.035x. 4 requests with 1 query token and no sink reach 1.016x. Batch 24 with 8320 keys each reaches 1.006x. On B200, these four cases reach 1.116x, 1.052x, 1.038x and 1.017x, and batch 32 with 4096 keys each reaches 1.007x.

**NVIDIA GB300 (sm_103a), CUDA 13.4**
