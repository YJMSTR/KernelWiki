## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
`flashinfer.sampling.softmax` on Blackwell (`cake_blackwell_softmax`) has one data type (FP32) and one layout (row-major `[rows, vocab]`). It can fuse a scalar or per-row temperature, and it can use PDL on sm_103a. As before, 14 Cake programs serve it: a warp program, a rowwise program, a bootstrap program, 7 row-caching cluster programs (1- to 16-CTA clusters x 4 or 8 tiles), 2 shared-tile programs (8- and 16-CTA clusters) and 2 persistent programs (8- and 16-CTA clusters, 8 tiles). This PR changes the persistent programs, the row-caching cluster programs, the shared-tile programs and the dispatcher. In the 2 persistent programs, each CTA writes row i one tile at a time. Right after each tile's store, it reads the next row's copy of that tile into the same registers. The stores drain while the next row is read, and the CTA-wide barrier before the next row's copies is gone. On sm_100a, a 16-CTA cluster that walks more than 24 rows refills its buffer one row at a time instead. Over a long walk on B200, the tile-at-a-time copies fall behind a row burst.
