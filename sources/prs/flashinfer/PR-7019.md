## 📌 Description

**Impact:** FP8 PrimTS dense MLA decode served by `throughput_2cta` (auto-selected when `num_heads * seq_len_q > 64`, e.g. 128 heads, or when it avoids a 1CTA split-KV) no longer slows down super-linearly at large batch.

| Measured on B200, H128, K8192 | Speedup |
|---|---|
| B128, page 16 | **2.40x** |
| B128-256, page 32 | **1.43-1.46x** |
| B128, pages 64/128 | 1.00-1.02x (main did not have the problem) |
| B32-64 | 1.01-1.08x |
| B ≤ 8 | within ±1% |

Outputs are bitwise identical to main. No API change. BF16 2CTA and the 1CTA kernel compile to SASS identical to main.

**Problem.** The FP8 split-MMA schedule's K and V loader warps read each K tile's page IDs from the block table in global memory. They do this *after* acquiring a free SMEM slot, and only then issue the TMA. Every K tile therefore pays a full global-load latency between slot release and TMA issue, on the critical path to the QK MMA. The cost grows with pages per tile (128 / page size).
- FP8 B128 K8192 page 32 took 198 us on main, against about 2 × 73 us expected from B64.
- ncu (B64 K8192 page 32): the QK MMA warp waits for K 49% of the time, and the K loader is stalled on the page-table load
