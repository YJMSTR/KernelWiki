TITLE: refactor(cake_dcp): one program per split-KV variant, batch size as a kernel argument

## Summary

Closes #5803. Was stacked on #5932 (and #5887); both merged on 2026-10-05 (e5192dd36d02, c9fc1c4d4db0) and this branch was rebased onto `main` after each merge with a byte-identical patch, so the diff GitHub shows is exactly this PR's one commit.

The DCP speculative-decode attention (`trtllm_batch_decode_with_kv_cache(..., causal_seqlens_kv_global=...)` → `flashinfer.cake_dcp.run_dcp_spec_decode(route="static")`) is regenerated from its source programs so that each static route ships one shape-independent program for both Blackwell architectures.

- **12 route instances (14 programs) replace 34 generated bodies**: `bf16_v1/retain{0,1}`, `bf16_v4/split{2,n}`, `fp8_d128/split{1,2,n}_retain{0,1}`, `fp8_d256/split{1,n}`; ten instances ship one text for both architectures, the two head_dim-256 FP8 instances ship one program per architecture (see below). The batch size is a kernel argument (the host passes the grid), so a new batch size no longer triggers an nvcc build on its first decode step.
