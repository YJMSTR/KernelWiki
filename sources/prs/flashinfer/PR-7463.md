## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
FlashInfer's `mm_bf16_fp4` multiplies BF16 activations by FP4 (E2M1) weights that carry E4M3 block scales, with FP32 accumulation. Cake ships it as two backend variants that differ in operand layout: `blackwell-native` (cuDNN-ABI layouts, BF16 or FP16 output) and `blackwell-tiled` (CuTe-ABI prepared-tile layouts, BF16 output). This PR regenerates 9 of the kernel's 97 Cake programs, with bit-identical outputs. The three two-CTA M=128 tcgen05 programs for 768/2112/2048 (`blackwell-native` with and without alpha, `blackwell-tiled` with alpha) now use a relaxed arrive at their start-up cluster barrier. The barrier-initialization fence already publishes the barriers, so the change drops the GPU-wide memory drain that the release arrive caused before any warp started its role. The two `blackwell-tiled` 8-CTA split-K reduce-scatter programs (with and without alpha) now issue their TMA loads before the start-up cluster rendezvous instead of after it. At M=1, each CTA now sends each peer only the one output row it stores, which is 64 bytes per peer instead of 1 KB.
