## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
`cake_fmha` balanced DCP speculative-decode attention handles a paged KV cache, context parallelism and several speculative q_len rows per request. Cake ships it as three families, all with BF16 Q and each with 32-row and 64-row packed instances: BF16 KV cache at head_dim 128 (`dcp_spec_bf16_balanced`), E4M3 KV cache at head_dim 128 (`dcp_spec_bf16_fp8_balanced`) and E4M3 KV cache at head_dim 256 (`dcp_spec_bf16_fp8_d256_balanced`). This PR changes the BF16 head_dim-128 and E4M3 head_dim-256 families by adding programs to the host `program` selector beside program 1, the device-planner program, which is each family's default, the previous Cake version on FlashInfer main and the baseline here. For BF16 head_dim 128 it adds programs 2-5. Program 2, the whole-tile static one-wave program, runs when a single request's block table keeps every (request, KV head) tile whole under one static wave (at most 112 pages of 16 tokens for 8 KV heads on 148 or 152 SMs), so every CTA issues its tile from its block index without the device planner.
