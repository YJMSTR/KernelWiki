## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Developed by the **CAKE team**. This PR follows up on #6324 (Round 2; motivation #6303). #6324 added `mm_nvfp4_lora` and `mm_fp8_lora`, which read the LoRA factors as given at run time. This PR adds an opt-in **prepared adapter** path for NVFP4. `prepare_nvfp4_lora_adapter(...)` returns a `PreparedNvFp4LoraAdapter` that folds the LoRA-up weight once: `B' = bf16_rne(fp32(lora_b) * (lora_scale / alpha))`, with the ratio computed as a single fp32 round-to-nearest division. `mm_nvfp4_svdquant` needs this same fold done offline. `mm_nvfp4_lora(..., lora_adapter=adapter)` then runs the new program `nvfp4_blackwell_svdq` (SM100, SM103) for every prepared call with K >= 2048; below that K floor a prepared call raises `ValueError` and the raw path must be used. The program accumulates base-first and has SVDQuant-equivalent numerics. If one of the adapter's source tensors (`lora_b`, `lora_scale` or `alpha`) has moved or been written since the prepare (a change of data pointer, version counter, shape or device; no value comparison), the call raises `StaleAdapterError` until the adapter is re-prepared.
