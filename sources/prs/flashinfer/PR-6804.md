## 📌 Description

This adds `flashinfer.sparse.qsa_sparse_paged_attention`, an experimental API for the main attention of the Qwen4Exp QSA layer over an NVFP4 KV cache on SM80 through SM90. It takes the same arguments as vLLM's Triton `qsa_sparse_paged_attention` plus the NVFP4 block scales `k_sf` / `v_sf`, and reads the paged layout written by `nvfp4_quantize_append_paged_kv_cache_with_slot_mapping`, so vLLM keeps its existing NVFP4 cache allocation and writer. vLLM's QSA layers take BF16 and FP8 KV today; with NVFP4 one token's K or V head is 144 bytes instead of 256.

The backend is in `flashinfer/experimental/qsa_nvfp4/`: a split-K kernel with one CTA per (row, KV head, split) over 64-token tiles, and an LSE merge that also applies the sigmoid output gate. NVFP4 is decoded straight into `mma.sync` fragments, and QK and PV both run on BF16 operands with FP32 accumulation. Only SM80 instructions are used, so one JIT module covers 8.0 through 9.0. Outside the package, the change is the thin entry point in `flashinfer/sparse.py` and one package-data line.
