## 📌 Description

This PR makes PrimTS decode (`fmha_decode`) faster in two ways: the kernel spends less time waiting on the softmax, and the paged planner picks a much better tile for multi-token decode.

### 1. Kernel: keep the tensor core busy while the softmax runs

In a two-instance Q128/KV128 Keeps tile, P overwrites S in TMEM. Each instance can therefore start its next QK only after its PV has consumed P, and the softmax of the next tile in turn waits for that QK. The result is a serial chain in which the tensor core sits idle while the softmax runs. This PR breaks up that chain:

- **16-bit K/V**: the softmax hands P to the PV MMA in four K32 fragments instead of one full row, so PV starts as soon as the first fragment is ready. On SM100, part of the exponentials move to the FMA pipe, and the kernel spills far fewer registers.
- **8-bit K/V (FP8 and Sage)**: P goes to SMEM instead of TMEM, and the softmax keeps the scores in registers. S is freed right after the max pass, so the next QK is issued before the current PV and runs alongside the exponentials.
