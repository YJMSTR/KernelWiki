## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
The MiniMax-H3 SM120 MLP block in Cake (RMSNorm + indexed AdaLN + FC1 + SwiGLU + FC2 + gated residual, using `mma.sync` + TMA on a single CTA) has two variants. One is per-token FP8 W8A8 (`minimax_h3_mlp_fp8_sm120`), which has a plain e4m3 instruction form and a `kind::mxf8f6f4` form, chosen per board. The other is NVFP4 W4A4 (`minimax_h3_mlp_nvfp4_sm120`). This PR adds no variant and changes no interface. It only changes ordering for correctness. In the SM120 FC1 and FC2 GEMM kernels, each `ab_empty` wait is now followed by `fence.proxy.async.shared::cta` before the TMA refills that ring stage. This applies to both MLP variants, both FP8 instruction forms, and the standalone SM120 FC1+SwiGLU ops (`minimax_h3_fc1_swiglu_fp8`, and `minimax_h3_fc1_swiglu_nvfp4` on CC 12.x). Compared with the Cake SM120 MLP now shipped on FlashInfer main, speed is unchanged within the measured spread: speedup is between 0.995 and 1.002 in every cell below.

Speedup = main / PR: the median over 6 rounds of the per-round latency ratio, each round timing both builds in separate processes on the same GPU. The ms columns are the median latencies over the same 6 rounds. M is the token count.
