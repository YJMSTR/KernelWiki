## 📌 Description

Adds `quant_mode="mxfp8"` (E4M3 weights and activations, E8M0 block-32 scales) to `cute_dsl_fused_moe` on
SM100/SM103. It reuses the W4A8 kernels with an FP8 B operand. It is also wired into the unified MoE API
(`QuantConfig(MXFP8, MXFP8)` with `CuteDslConfig`) and the `unified_moe` benchmark.

**Why CuTe-DSL:** new activations are simple to add to this kernel, and they are planned for future Nemotron models.

**Changes**
- MXFP8 weight dtype through `_moe_core_impl` and the tuner.
- `convert_row_major_sf_to_mma_layout` for checkpoint scales.
- Unified-API runner, weight and activation preparers.
- Tuner fix: GEMM2 K for unpacked weights.
- Benchmark: `trtllm` and `cute_dsl` backends; pass the runner launch state.
- GEMM1 N=192 tiles for non-gated activations, only when the intermediate size is a multiple of 192 (separate commit).

This PR was tested with Nemotron 3.5 Super (non-gated ReLU² MoE), end to end in vLLM and with unit tests on synthetic ReLU² shapes. Gated activations (SwiGLU, GeGLUTanh) run on the same kernels as W4A8 and should work, but are not yet tested with MXFP8 weights; SiTU is not supported.
