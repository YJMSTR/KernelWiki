## Summary

The shared scan lowering added a participating-thread offset in #3536, but the CuTeDSL scan helpers still accepted the old constructor arguments. Generated calls such as `tl.CumSum1D(32, False, 0).run(...)` therefore fail with a constructor argument error. The stale codegen assertions also caused the two CUDA CI failures in #2815.

## Changes

- Accept an optional `thread_offset` in the 1D and 2D cumsum/cummax helpers, preserving existing calls with a default of zero.
- Subtract the offset before selecting the participating lane and warp, matching the enclosing thread range used by scan lowering.
- Update the existing codegen assertions to include the offset and mark these CUDA-specific tests with `requires_cuda`.
