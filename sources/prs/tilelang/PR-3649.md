Fixes #3648.

## Problem

The `cython`, `nvrtc` and `cutedsl` adapters accept `stream=` and launch on it, but allocated the `out_idx` outputs with `torch.empty` on the current torch stream. The caching allocator orders reuse of a block only after earlier work on the stream it was allocated on, so the output could be a block with work still queued on the current stream; that work then overwrote the kernel's result (repro in #3648: 4/5, 5/5 and 5/5 corrupted outputs on H100).

## Change

- `tilelang/jit/adapter/base.py`: `output_allocation_stream(stream, device)` returns the caller's stream when it differs from the current stream, otherwise `None`. A zero handle maps to `torch.cuda.default_stream(device)`, because `ExternalStream(0)` yields a pooled stream on PyTorch 2.4/2.5.
- `cython_wrapper.pyx`, `nvrtc/adapter.py`, `cutedsl/adapter.py`: when the caller passes `stream=`, outputs are allocated under that stream. Without `stream=` nothing changes (no extra call on the default path).
