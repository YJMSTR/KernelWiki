## Summary

NVRTC and CuTeDSL host wrappers use raw Var names in generated signatures and match arguments against printed device names. Distinct Vars can share a name hint; user names can also collide with wrapper-owned names (`stream`, `device_id`, `ctypes`, etc.). Device lowering may rename or reorder parameters independently.

- Allocate wrapper argument names by Var identity while preserving the positional ABI.
- Bind device arguments and launch expressions using lowered host-call arguments. CuTeDSL preserves repeated calls of the same kernel with different scalar bindings. NVRTC still retains one call per kernel name, as on the base; changing that behavior is outside this PR.
- Preserve distinct same-hint shape/stride symbols and reject ambiguous name-only fallback.
- Keep explicit shape scalars in the primary argument list instead of appending them again.
- Preserve TMA descriptor-to-buffer bindings.

Related to #3413. The first two commits separate the NVRTC and CuTeDSL changes; both reuse the optional identity map in expression rendering.
