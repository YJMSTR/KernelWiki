## Summary

Follow-up to #3153 (stacked on it — the first commit here is that PR). The `make_<type>_<N>_t` constructor ladders and several `BroadcastNode` special cases hand-enumerated the (dtype × lanes) matrix, so every new dtype or vector width required another hand-written constructor — the same failure mode #3153 fixed cell-by-cell. This PR replaces the enumeration with two generic templates (CUDA only; the HIP headers keep their own definitions):

- `tl::make_vec<V>(e0, e1, ...)` — builds a vector struct from one scalar element per lane (byte-sized or larger elements).
- `tl::make_fp4_vec<V>(e0, e1, ...)` — same for nibble-packed fp4.

**Deleted:** `make_fp4_e2_{2..32}_t` (5 functions) and `make_fp8_{e4,e5,e8}_{2..32}_t` (15 functions). `#pragma unroll` over the element array produces the same SASS as the hand-written ladders; a wrong argument count is now a `static_assert` with a readable message instead of an "identifier undefined" nvcc error at a missing rung.
