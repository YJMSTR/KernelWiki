## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
SM121 (GB10, DGX Spark) runs the SM120 warp-level block-scaled MMA, but `tl::sm120_mma_sync_blockscaled` only checked `CUTLASS_ARCH_MMA_SM120A_ENABLED`. CUTLASS defines that macro only when `__CUDA_ARCH__ == 1200`, so on `sm_121a` every block-scaled MMA compiled to `BPT.TRAP` instead of `OMMA.SF`.

Changes:
- `mma_block_scale.h`: accept the arch-specific and family-specific SM120 and SM121 targets (`CUTLASS_ARCH_MMA_SM12{0,1}{A,F}_ENABLED`); ptxas accepts `mma.block_scale` for `sm_120a/f` and `sm_121a/f`.
- NVF4 GPU tests: gate on the SM12x family instead of compute capability 12.0 exactly, so they run on SM121, and compile the one runtime test that pinned `sm_120a` for the device's own arch.
- CuTeDSL backend: allow `sm_121`/`sm_121a` in the TMA arch list.

Testing on a DGX Spark (GB10, `sm_121a`, driver 580.178.04, CUDA 13.0) with this branch:
- `test_tilelang_language_nvf4_mma_block_scale.py` and `test_tilelang_quantize_nvfp4_scale_layout.py`: 162 passed.
- SASS of the NVF4 block-scaled codegen kernel (256 x 256 x 256, 3 stages) compiled for `sm_121a`: with main's `mma_block_scale.h`, 32 `BPT.TRAP` and no `OMMA`; with this branch, 32 `OMMA.SF.16864.F32.E2M1.E2M1.UE4M3.4X` and no
<!-- upstream-excerpt-end -->
