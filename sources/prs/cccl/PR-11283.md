## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
kills two birds with one stone

closes https://github.com/NVIDIA/cccl/issues/10766 and fixes https://github.com/NVIDIA/cccl/issues/11282

Makes `ArgMin/Max` tunable per-input-type (not per key-value-pair combination) AND disambiguates `ArgMinLastMax` from `ArgMin/ArgMax`. Both are granularity fixes: the benchmarks already measure at this granularity, but the reduce `policy_selector` was coarser, so measured winners could not be encoded (#10766) and `ArgMinLastMax` silently borrowed an `ArgMin/ArgMax` entry at the colliding 16-byte accumulator size (#11282).

1. ArgMin/ArgMax: per-input-type tunings are now encodable. The selector can finally tell KeyValuePair<int, float> from KeyValuePair<int, int>
2. ArgMinMax: has its own identity, own tunings. `op_kind_t::argminmax`

### Behavioral Change
- `ArgMinLastMax` on int/float stops using the borrowed `ArgMin` tuning and runs the default until dedicated tunings land in a follow-up PR (may be temporarily slower than the accidental borrow).
- Custom operators with custom accumulator structs no longer match `arg-extremum` tunings by size coincidence.
- `ArgMin/ArgMax` behavior is unchanged everywhere
