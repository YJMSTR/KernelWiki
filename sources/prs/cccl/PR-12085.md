## Description

The bugs have been found during the application of clang-tidy `misc-header-cleaner` to CUB.
There are two header inclusion cycles that involve CUB configuration/utility headers:

**(1) (the simple one)** : `cub/util_arch.cuh`, `cub/config.cuh`, include each other.

The fix is just replace `<cub/config.cuh>` with `<cuda/__cccl_config>` (same as `util_macro.cuh` and `util_cpp_dialect.cuh`).

</br>

**(2) (the hard one)**:  `cub/util_device.cuh` and `cub/detail/launcher/cuda_runtime.cuh` include each other.

`cub/util_device.cuh` includes `cub/detail/launcher/cuda_runtime.cuh` to access to `cub::detail::TripleChevronFactory` definition for `KernelConfig`.
The PR moves `KernelConfig` + `CUB_DETAIL_DEFAULT_KERNEL_LAUNCHER_FACTORY` macro directly to  `cub/detail/launcher/cuda_runtime.cuh` to avoid dependencies/forward declarations.

On the other hand, we need to also update all device dispatch files because they previously relied on `cub/util_device.cuh`.
Finally, the fix found that 3 thrust headers were not self-contained. Same here, the headers relied on `cub/util_device.cuh` implicit inclusion of the launcher functionality of CUB.
<!-- upstream-excerpt-end -->
