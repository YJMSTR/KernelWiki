## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
`baseline_topk_policy::worker_per_segment_policies` was a fixed `cuda::std::array<worker_policy, 6>`, forcing every tuning to specify exactly 6 worker policies. We want a dynamic count instead.

`std::vector` won't work during constant evaluation in C++17, neither does a custom container type relying on dynamic allocation.

The actual motivation to do this now is because @anikaj-eng requires dynamic sub policies as well for a new segmented sort implementation, so I am experimenting here whether `inplace_vector` is feasible.
