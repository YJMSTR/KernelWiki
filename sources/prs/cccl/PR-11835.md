## Description
closes #11834

With a pinned tie-break (`prefer_smaller_index` / `prefer_larger_index`), `DeviceBatchedTopK` ranked -0.0 below +0.0, so when the k-th boundary fell among zeros the index preference only applied to the bitwise-equal zeros. `extract_bin_op_t` and `identify_candidates_op_t` gain a `NormalizeMinusZero` template parameter and, when it is set, apply `ProcessFloatMinusZero` after `TwiddleIn`, the same normalization `DeviceRadixSort` use. The cluster agent sets it for `prefer_smaller_index` / `prefer_larger_index`, `DeviceTopK` passes `false`. Both ops have to change together because `kth_key_bits` is built from the first one and compared in the second. It's an identity for non-floating-point keys, and output keys are still copied from the input, so -0.0 comes out as -0.0.

The new test uses float keys from {-1, -0, +0, 1} with k chosen so the boundary lands inside the zeros of every segment, for both directions and both tie-breaks, on single-CTA and multi-CTA segment sizes.
