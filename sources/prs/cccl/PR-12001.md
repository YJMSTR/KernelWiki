## Description

<!-- Every PR should have a corresponding issue that describes and motivates the work done in the PR -->

closes https://github.com/NVIDIA/cccl/issues/8466

The check itself is pretty much a carbon copy of https://github.com/llvm/llvm-project/blob/main/clang-tools-extra/clang-tidy/modernize/TypeTraitsCheck.cpp except for two important differences:

1. We apply it to `cuda::std` AND `cuda::` instead of `std::`.
2. We want to automatically pick up any trait additions as they are added.

The first change is mostly an architectural change. Instead of handling just a single namespace, we potentially need to handle a few namespaces. Not that bad.

But the second is tricky because we can do it a few different ways. We can check for new traits every time we run clang-tidy (this ensures we are always up to date), but this is very very very expensive. Or we can do it by pre-generating a catalog of known traits that have a `_v` and `_t`. But then how to decide when to generate the catalog and when it is out of date? We do this by putting a "test" in that scans the current headers and errors out if the catalog is outdated.
