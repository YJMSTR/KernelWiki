Closes https://github.com/NVIDIA-dev/cccl_qa_agent_findings/issues/489

`DeviceTopK` only implements `require(determinism::not_guaranteed, output_ordering::unsorted)`, so an explicit
`tie_break::prefer_smaller_index` / `prefer_larger_index` was accepted and silently ignored, although both the class docs and `docs/cub/device_topk_requirements.rst` promise a compile error.


- `device_topk.cuh`: `static_assert` that tie_break is not placed outside `require(...)` (as DeviceBatchedTopK does) and
  that any specified tie_break is `tie_break::unspecified`.
- Not changed: omitting tie_break entirely, i.e. `require(not_guaranteed, unsorted)`, the only accepted form since
  CCCL 3.2, stays accepted - it would be a breaking change otherwise. The determinism/tie_break pairing rule (both specified or both omitted) that `DeviceBatchedTopK` enforces would reject it and remains deferred to CCCL 4.0. The TODO now says so explicitly and links #3701. The class note and the requirements page recommend the forward-compatible spelling `require(not_guaranteed, tie_break::unspecified, unsorted)`.
