## Description

Fix Cooperative reduction - Block of

- cccl_private/issues/927
- cccl_qa_agent_findings/issues/29

False positive:

- **P2: raking reads uninitialized shared memory**

Actual issues:

- **P1: the nondeterministic algorithm uses atomic add for every operator**. In `BLOCK_REDUCE_WARP_REDUCTIONS_NONDETERMINISTIC` specialization, the implementation always add the values, regardless the operator.
- **P2: num_valid > BLOCK_THREADS**. BlockReduce specializations relies on `num_valid` instead of performing the computation with a full tile. Simple fix: always pass `BLOCK_THREADS` in this case.

Additional issues found during the investigation, not related to [QA Agent]:

- `BLOCK_REDUCE_WARP_REDUCTIONS_NONDETERMINISTIC` specialization ignores `num_valid` in the `atomicAdd` step. This implies that warps with no valid items add the input of the first lane (poison value). Fixed in this PR
- `BLOCK_REDUCE_WARP_REDUCTIONS_NONDETERMINISTIC` specialization does not handle custom operators and rely on `T{}` for the identity.

  - https://github.com/NVIDIA/cccl/issues/11647
