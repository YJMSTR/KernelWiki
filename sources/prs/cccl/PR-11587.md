## Description

Part of #9875 (the `DeviceMergeSort` row).

Replaces the trailing `cudaStream_t` parameter of the two-phase `SortKeys`, `SortKeysCopy`, `SortPairs`, `SortPairsCopy`, `StableSortKeys`, `StableSortKeysCopy` and `StableSortPairs` overloads, and of the private `*NoNVTX` helpers behind them, with an execution environment (`const EnvT& env = {}`). The two-phase overloads now go through `detail::dispatch_with_env_and_tuning` with user-provided storage, so they honor `cuda::get_stream` and `cuda::execution::tune` the same way the single-phase overloads do. This follows the pattern of the merged sibling refactors (#9416, #9455 to #9459, #9463, #9464, #9552 to #9555, #11013).

Existing callers keep working: a `cudaStream_t` or `nullptr` passed in the last position is accepted through `cuda::get_stream`, and a literal `0` still compiles and runs on the default stream. Callers checked:

- Thrust calls `detail::merge_sort::dispatch` directly and is unaffected.
- `cuda::std::__pstl` sort and the cudax multi-GPU HSS sort use the single-phase overloads and are unaffected.
