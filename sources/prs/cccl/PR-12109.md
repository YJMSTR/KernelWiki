## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
`cub::DeviceReduce::ReduceByKey` compares keys after converting them to the unique-output key type, so a lossy conversion merges distinct runs. For example, `int` keys `{1, 257, 513, 2, 2}` with `uint8_t` output keys give 2 runs instead of 4.

Keys are now loaded and compared as the input key type and converted only when written. The first commit adds a regression test that fails without the fix. Found while porting `thrust::reduce_by_key` to CUB in #5583.
