## Upstream PR description (verbatim excerpt)

Reverts #164 (commit abf5b4b).

PR #164 removed the explicit `cute.arch.elect_one()` election around the G2S `cute.copy(CopyBulkG2SOp)` calls in `cpasync_bulk_get_copy_fn`, assuming the CUTLASS DSL `cute.copy` lowering emits the required single-lane election internally for async bulk copy atoms.

After further discussion, we're reverting that change and restoring the explicit election, so these G2S bulk-copy paths stay correct on DSL builds where `cute.copy` does not emit the election itself. This restores the `with cute.arch.elect_one():` wrappers around both `copy_bulk` and `copy_bulk_single_stage`. The S2G `cp.reduce.async.bulk` path was never changed and is unaffected.

Sorry for the late changes.
