## Purpose
Refactor DeepGemm MegaMoE integration behind a DeepGemmMegaMoEBackend abstraction to unblock non-SM100 backends; no behavior change on SM100. The DeepGEMM MegaMoE kernel is a very high-performance MoE implementation, and is expected to be reused by more models and hardware. For example:
- An equivalent MXFP4 MegaMoE on SM90, where the activation quantization scheme has to change to fit the hardware and different precision requirements.
- Today MXFP4 MoE weights are the default; follow-ups will likely need FP8 and other weight formats on top of the current implementation.

This PR adds an abstract DeepGemmMegaMoEBackend so more models can enable the DeepGEMM MegaMoE kernel quickly, and so external vLLM plugins can support more scenarios flexibly.

Main changes:
- DeepGemmMegaMoEBackend currently exposes transform_weights (routed / shared), bf16_mega_gate, run_mega_moe, supports_shared_experts, and supports_bf16_mega_gate; it also abstracts mma_type and the hidden-state activation scheme.
