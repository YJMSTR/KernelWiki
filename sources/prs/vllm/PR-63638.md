## Overview

Adds an opt-in MLA attention backend for Kimi-K3 on Blackwell, `--attention-backend KIMI_K3_KV_BALANCED_MLA`. Its decode splits each request's KV by its own length, so the decode stays balanced across the GPU when the context lengths in one batch differ a lot, as they do in agentic workloads. It is a standalone backend built on the common MLA backend classes (`MLACommonBackend`, `MLACommonImpl`, `MLACommonMetadataBuilder`); it does not depend on `TOKENSPEED_MLA`. The code lives in `vllm/models/kimi_k3/nvidia/kv_balanced_mla/`. Outside it, the PR only adds the backend's entry to `AttentionBackendEnum` (as the DeepSeek V4, MiniMax M3 and Step5 backends in `vllm/models/` have).

## Claims

- **Decode attention, AgentX context lengths on GB300:** 1.34–1.59x faster than `TOKENSPEED_MLA` with `tokenspeed_mla_min_split_kv=8`, and 1.91–2.67x faster than its default (geometric mean over batch sizes, DEP16 and DCP8, target verify and draft).
- **End-to-end, AgentX on GB300:**
  - DEP16 decode (3P1D c336): +7.8% TPS/GPU and +20% p90 interactivity.
  - DCP8 decode: +4.6% TPS/GPU and +10% p90 interactivity at 3P4D c240, and +2.7% / +13% at the prefill
