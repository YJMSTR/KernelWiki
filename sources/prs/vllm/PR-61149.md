## Overview

Bump the vendored DeepGEMM pin to the tip of `vllm-project/DeepGEMM` `dev` (`6ce1c5e`): upstream's 26/09/30 public release (vllm-project/DeepGEMM#30, deepseek-ai/DeepGEMM#462) plus vendoring import fixes (vllm-project/DeepGEMM#31, vllm-project/DeepGEMM#32) and a relaxed paged sparse MQA page-stride guard (vllm-project/DeepGEMM#33). Adapt vLLM to the breaking MQA-logits API.

## Claims

- vLLM builds, vendors and imports DeepGEMM 2.8.1.
- The DSA sparse indexer (DeepSeek-V3.2, GLM-5.x, GLM-5.3, DeepSeek-V4/V4.1, HY-V4) keeps working on SM90/SM100/SM120 with the new MQA-logits API.
- On SM100 the FP8 indexer cache stays numerically identical: same FP8 values and the same per-token power-of-two scale, now stored as four packed UE8M0 bytes (a valid MXFP8 encoding) because SM100 MQA kernels only take MX scales.

## Breaking changes in DeepGEMM `1e1842a` → `6ce1c5e`

| Change | vLLM impact | Handling |
|---|---|---|
| `deep_gemm/__init__.py` imports a new `deep_gemm/locality_domain.py` | not vendored → `import vllm.third_party.deep_gemm` fails | install it in `deepgemm.cmake` |
| `_C.py` registered the locality-domain shim as `deep_gemm._C.locality_domain` | relative import
<!-- upstream-excerpt-end -->
