## Description

Two ordering fixes in the Kimi K3 attention-residual kernels (`cpp/tensorrt_llm/kernels/kimiK3AttnRes/`).

**1. `attn_res_fwd_online_v2_kernel`: order the `ws_stats` reads before the next chunk's writes.**
- **What goes wrong:** the kernel reuses one `ws_stats` buffer for every chunk of candidates. Lane 0 of each consumer
  warp writes its row, and a named barrier orders those writes before every consumer's cross-warp reads. Nothing
  orders the reads before the next chunk's writes. With more than one chunk (N > 4 at H 7168), a warp that has
  finished reading can overwrite its row while a slower warp still sums it.
- **Before:** under compute-sanitizer racecheck, which serializes warps (a legal schedule), every call with N >= 5
  returned a wrong mixture (140 / 140 calls, relative error 0.6-2.1 of max |ref|). Natively it was not observed (0 of
  200 repeats).
