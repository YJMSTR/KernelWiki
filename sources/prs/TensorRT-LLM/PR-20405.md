## Description

Long Gemma3/Gemma4 multimodal prefills can OOM while constructing a dense attention mask because the existing implementation materializes several quadratic intermediate tensors and copies per-request masks into a packed batch buffer. Construct the packed boolean mask directly with a shared Triton kernel, using only linear-sized vision-blob metadata in addition to the final output.

Preserve causal/sliding-window attention, same-blob vision bidirectionality, Gemma4 cached-prefix handling, audio causality, and the existing model-specific gating. The final dense mask still requires Q*(P+Q) bytes per request.

On one B200, warmed mask-construction peak allocated memory (including the output, window 1024, one request with no cached prefix) was:

| Model | Query length | Before | After |
| --- | --- | --- | --- |
| Gemma3 | 32K | 5.00 GiB | 1.00 GiB |
| Gemma3 | 64K | 20.00 GiB | 4.00 GiB |
| Gemma4 | 32K | 3.00 GiB | 1.00 GiB |
| Gemma4 | 64K | 12.00 GiB | 4.00 GiB |
