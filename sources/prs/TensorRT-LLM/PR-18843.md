## Summary

Move model-specific cache-manager behavior out of the shared Mamba cache-manager package. The common package retains the pool lifecycle, layout and acceptance data, state protocol, and legacy compatibility surface.

- Mamba2, GDN, KDA, and Qwen4 own their replay/intermediate state in their respective module directories. GDN does not inherit Mamba2 replay behavior.
- `_initialize_spec_state()` supplies an optional implementation of the `MambaState` protocol. The V2 base delegates buffer access, binding, slot reset, accepted-state updates, layer-cache construction, and shutdown through that protocol.
- Kimi K3 and GLM 5-next retain model-owned KDA suspend/resume, transferred-state seeding, and replay-pool binding. The common base does not inspect concrete replay types.
- Qwen4 owns PLE/QSA layout access; Mamba2 owns its random-seed accessor. Registered persistent-buffer roles drive warmup cleanup, preserving the existing scratch/index/seed lifecycle.

[Architecture and interface documentation](https://mamba-hybrid-manager-architecture.lfy.nvidia.com/) (NVIDIA internal).
