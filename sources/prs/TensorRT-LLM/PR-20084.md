## Description

**Problem:** The merged-weight KDA prefill projection computes `W @ x^T` so the GEMM writes the channel-major `[3D, T]` conv input directly. Its output rows are `T * element_size` bytes apart; when that isn't a multiple of 16, cuBLAS can't use its TMA kernels and falls back to a much slower `align1` kernel. Prompt lengths are arbitrary, so about 7 in 8 prefill batches hit this. Fixed-length benchmarks (e.g. 13312 tokens) miss it.

**Fix:**
- Aligned T keeps the transposed GEMM. It is also the faster path there: the in-place channel-major conv is about 2x faster than the channel-last one on a long single sequence (96 vs 190 us at T=13312).
- Unaligned T runs the token-major `F.linear` and passes its transposed view to `causal_conv1d_fn`, which selects the channel-last kernel. That kernel returns a new tensor, so `forward_prefill` now keeps the return value.
- `fused_kda_post_conv` reads either layout through strides (see "Post-conv strides").

The FP8 fused `Linear` and separate q/k/v paths are unchanged. Kimi models share this code and benefit too.
