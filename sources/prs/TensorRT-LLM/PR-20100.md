## Summary

Opt-in deterministic mode for the fp32 self-sampling GVR V2 top-K decode kernel (`gvr_topk_decode_self_sampling`): `deterministic=True` gives a repeatable index set and a repeatable output order, `sorting="ascending"` additionally sorts each row. The default arguments run the unchanged original module (bit-identical to `main`).

Why: the production kernel reserves output positions through atomics, so the output order follows arrival order even when every score is distinct, and when scores tie at the K-th boundary the selected set itself follows arrival order. Bitwise reproducibility of the indexer (and anything downstream) is impossible without a defined rule.

What changes:

* `run_varlen` / `run` / `run_ws` / `warmup_varlen` and the prefill entry points `run_prefill` / `prefill_ready` / `warmup_prefill` gain `deterministic: bool = False` and `sorting: str | None = None`; `TopK(...)` gains `gvr_deterministic` / `gvr_sorting` and forwards them on both its decode and prefill self-sampling branches. Nothing else in the default path changes.
