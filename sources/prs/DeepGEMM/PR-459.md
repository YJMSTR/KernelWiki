## Summary

Two small follow-ups to #447 for the DSv4.1 sparse MQA logits, found while integrating `nv_dev` into TensorRT-LLM (index cache pages are 64 x (64 + 4) = 4352-byte page-footer pages, and CUDA graphs are captured on a side stream). No kernel algorithm changes.

1. **Accept 16-byte aligned KV pages in the paged sparse MQA logits.** `fp8_fp4_paged_sparse_mqa_logits` required `fused_kv_cache.stride(0) % 512 == 0` (host and device asserts). The paged accessor only computes `page = base + page_idx * kv_page_stride_bytes` and copies the KV / SF blocks with 16-byte `cp.async` chunks, so 16-byte alignment is the actual requirement (the cache base pointer is now checked for it as well). Caches whose page stride is not padded to 512 bytes can be read in place.
2. **Reuse a warmed sparse MQA logits workspace during graph capture.** The per-stream workspace asserted that its first allocation never happens under capture. Frameworks that capture on a dedicated side stream but replay on the stream they warmed up hit that assert on the first captured metadata call.
