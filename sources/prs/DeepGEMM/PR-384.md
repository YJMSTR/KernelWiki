## Summary

Merges upstream `559d79f` (`#377`, Public release 26/07) into `nv_dev` at `a6b593d` (`#369`). This also brings in upstream `#364` and the race fix from `#343`; the merge base is `88965b0`.

The branch uses the same explicit non-fast-forward topology as the previous `nv_dev` sync PRs (`#314`, `#328`, and `#349`), keeping the upstream main commit as the merge commit's second parent.

B200 validation exposed two SM100 FP16-weight MQA synchronization gaps in the PTX-wrapper migration. Follow-up `96fbced` elects one lane for raw-PTX 2x1SM UMMA issue, waits for each CTA's local KV-scale TMA before consumption, and fences the TMEM producer/consumer handoff.

## Conflict resolution

- Adopted `#377`'s unified SM100 MQA and common MMA/PTX refactor while retaining nv_dev's SM90 `next_n=4` multicast and `block_kv=32`, dedicated SM120 paths, FP16/BF16 weights, and 16-head indexer support.
- Preserved metadata safety for empty/zero-context requests and made producer Q prefetch follow the scheduler's actual next task.
- Ported the FP16-weights path to the new headers, with padded host offsets, correct per-warpgroup row indexing, and per-row compressed-window bounds.
- Guarded the SM9
