## Agent Notes

This fixes wrong output from the SM100 forward with CLC and 2CTA, and makes the forward's work-tile coordinates
explicit so the same mistake cannot recur.

**Bug.** With 2CTA, both CTAs of a cluster must work on the same pair-level work tile: rows come from
`(m_block * q_stage + stage) * cta_group_size + mma_tile_coord_v`. The CLC scheduler counts as persistent, so the
forward passed `use_cluster_idx=False` and a CTA-level `num_block`; `clc_work_to_coords` then gave each CTA
`block_idx * 2 + rank`. The two CTAs disagreed on their tile and the 2CTA MMA mixed Q rows from different tiles. On
GB300, `FA_CLC=1` on K-only varlen packed GQA hd128 had max error 0.39 vs fp32; with the fix the output is bitwise
equal to the non-CLC kernel. This bug was also the cause of the hd256 2CTA CLC exclusion, which stays in place here.
