### Human note

Pure refactor PR

## Problem

Each of the four warp roles in the SM100 hd256 2CTA forward kernel (load, MMA, softmax, correction)
rebuilt the per-batch Q/K lengths and offsets by hand, in about 35 near-identical lines: cu_seqlens reads,
seqused overrides, the paged static KV length, and the varlen tile check. Each role then called the
`Sm100FusedMask.get_trip_*_via_block_info` helpers, which construct a fresh `BlockInfo` and a dummy
`SeqlenInfoQK` on every call. The roles must agree exactly on skips and KV ranges or the pipelines
deadlock, and four copies make that easy to break.

## Fix

The kernel now builds one `BlockInfo` and one `SeqlenInfoQK.create` factory before the role dispatch, the
same pattern `FlashAttentionForwardSm100` uses. Every role does
`seqlen = SeqlenInfoCls(batch)` → `block_info.get_n_block_min_max(seqlen, m_block)` →
`if self.tile_has_work(seqlen, m_block)`. The causal/local mask bounds call
`block_info.get_n_block_min_causal_local_mask` / `get_n_block_min_before_local_mask` directly.

This is a refactor with no intended behavior change (+76/−180 in one file).
