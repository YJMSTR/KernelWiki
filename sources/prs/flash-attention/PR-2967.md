## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Packs the `qhead_per_kvhead` query heads of a KV head into the rows of the Q tile, the way the forward's `pack_gqa` does: one tile per KV head, K/V loaded once, dK/dV kept in TMEM and stored directly (no fp32 accumulate, no postprocess).

**Series**
1. Tests first, named 2CTA schedules and TMEM widths (#2964)
2. 64-row KV tile per CTA (M=64 TMEM layout) with GQA, varlen and deterministic support (#2965)
3. hdim 256 on the general kernel (opt-in) (#2966)
4. **Pack the query heads of a KV head into the Q tile (GQA)** ← this PR
5. Cheaper deterministic dQ semaphore release (#3058, on main, independent; needed for the deterministic numbers of 7)
6. Pack 2 query heads per tile and loop the KV head's remaining heads inside the CTA (#3059, stacked on this PR)
7. Make it the default and delete the dedicated kernels (#2968)

Steps 5–7 are the result of the hd256 perf audit after step 3: the general kernel still lost to the dedicated pair on deterministic, on small / odd GQA ratios at short seqlen and on causal MQA.
