Related: #2374, #2999, #2407. SM100 backward counterpart: #3012 (merged as `2bdeddd1`; this PR is rebased onto it and only carries the SM90 commits). SM100 forward counterpart: #2983 (merged).

## Problem

Whenever the logical K length is shorter than the buffer — packed varlen (`cu_seqlens_k`) or dense `(b, s, h, d)` with `seqused_k` — the SM90 forward and backward TMA-load whole K/V tiles, so rows in `[seqlen_k, tile_n)` arrive as whatever the buffer holds past the end. Masking makes `P` and `dS` exactly zero there, but `0 * NaN = NaN`:

- forward: `O = P @ V` reads the V tail → NaN output (the #2374 / #2999 report on Hopper). A NaN K tail is harmless (masked to -inf before exp).
- backward: `dP = dO @ V^T` reads the V tail and `dQ = dS @ K` sums over the whole K tile → `dQ` all-NaN from a NaN tail in **K or V**, for every sequence whose last K tile straddles the tail; `dK`/`dV` stay finite. Independent of the forward: with a finite `O` and `D`, `dQ` is still NaN. In the dense layout this is the worse case: once the forward is bounded, `O` and the loss are clean and only the gradient is NaN.

## Fix

Same change as #2983 / #3012: build the V (forward) and K, V (backward) TMA desc
