## Summary

I think the synccheck is pre-existing ill put a foolow up pr on top

Enable hd256 SplitKV in the general forward by staging fp32 output in two 128-column chunks. This halves `sO` from **128 to 64 KiB**, leaving room for **two KV stages instead of one**. A barrier protects buffer reuse between chunks. Only actual `head_dim_v == 256` uses this path.

## Performance

**1.11–1.51× faster** on four SplitKV decode cases; no-split control unchanged.

![Full-buffer versus chunked hd256 SplitKV latency](https://github.com/user-attachments/assets/4856cdd7-0953-4583-9b93-440d1a8f92ed)

GB200, BF16, forward+combine; three alternating A/B rounds, fixed-pointer CUDA graphs, no L2 flush. Tested stack `33985c6e` against the same source with this PR reverted and the hd256 SplitKV guard relaxed (the unmodified parent rejects it). This isolates the patch, not dedicated-versus-general performance. Default power policy; the largest case ran at different clocks (~1.5 vs 2.06 GHz), so this is not a same-clock comparison.
