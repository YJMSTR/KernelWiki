## Problem

#2983 / #3012 / #3013 bound the K/V TMA loads of varlen and `seqused_k` calls by the logical sequence length through a 5-D descriptor whose rows axis wraps modulo 2^64 (`create_ragged_tensor_for_tma_load`). The TMA unit does not clip its address translation to the rows that are in bounds: for a partially out-of-bounds tile it prefetches up to ~128 KB past the box, and because that descriptor's footprint is unbounded, nothing stops it at the end of the tensor. When the memory after V (or K) is unmapped the kernel faults with `cudaErrorIllegalAddress`. PyTorch's caching allocator usually leaves mapped memory there, which is why it only showed up as an order-dependent failure in the test suite (#3068).

A stand-alone reproducer places V at the end of a fresh 1 GiB allocation with the caching allocator disabled: every `seqlen_k < 128` faults on main, and the real-extent descriptor used before #2983 never does.
