## Upstream PR description (verbatim excerpt)

<!-- upstream-excerpt-start -->
Inspired by TLX's SMEM free simple [dq postprocess kernel](https://github.com/facebookexperimental/triton/blob/a05314cb02afddf4bd617eb072e7a2641b6de172/third_party/tlx/ops/kernels/flash_attn/sm100.py#L1293), I took a closer look into FA4's postprocess kernel and tried to reduce its SMEM access and found good perf wins (up to about **2x perf**) with simpler implementations for the SOTA **SM100 2cta** cases.

The main change is to use G->R load directly to replace the first G->S->R sequence. According to the GMEM layout, it's
valid to do so without losing 128b load benefits and memory coalescing.

## Existing behaviors
I try to summarize the important memory buffer layouts taking `tile_m=128`, `tile_hdim=128` and `(b=4, h=48, s=1024, d=128)` for example.

Right now the kernel roughly has these few steps:
- G->S loads dQaccum 32b elements
  - From the bwd main kernel `dQacc_reduce` we can see how the data moved from TMEM all the way to GMEM and
end up with the layout `mdQaccum: (4, 48, (64,2,8), (4,16,2)) : (6291456, 131072, (4,8192,16384), (1,512,256))`
- S->R continue loading into rmem
- multiply by a scale, and downcast to 16b elements
- layout conversion by R->S, S->R
  - Right no
