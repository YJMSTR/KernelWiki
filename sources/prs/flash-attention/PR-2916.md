## Problem

The dedicated SM100 hd256 2CTA forward kernel asserted `not is_split_kv`, so every hd256 call ran with one
split. For batch-1 decode and short-chunk shapes, that launches only a few dozen CTAs on a 148/152-SM part.
The kernel then streams all of the KV through a small fraction of the GPU.

## Fix

- **Kernel** (`sm100_hd256_2cta_fmha_forward.py`): writes fp32 O and LSE partials with a leading split dim.
  `_flash_attn_fwd_combine` then merges them, the same path the generic SM100 kernel uses.
  - The static grid folds splits into grid y (`head * num_splits + split`). The varlen scheduler
    (`max_seqlen_q=None`) puts the split on grid y. Both CTAs of a cluster share y/z, so they always agree
    on the split.
  - All four warp roles call the same `decode_work_tile` / `get_kv_block_range` and use one skip predicate.
    `get_kv_block_range` wraps `BlockInfo.get_n_block_min_max` with the split.
  - With ceil-divided ranges and causal tiles, a split can own no KV blocks, and its count can be negative.
