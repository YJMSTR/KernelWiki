## Summary

- Bound dedicated SM100/SM110 HD256 varlen forward, dQ, and dK/dV grids by runtime maximum sequence lengths instead of packed total-token extents.
- Preserve packed output alignment for vector stores.
- Use TMA stores for complete 128-row dQ tiles while retaining predicate stores for ragged tails.
- Add targeted MQA correctness coverage for complete and ragged tiles under causal and noncausal masking.

This closes #2521. Thanks to @horakka5 for the original root-cause analysis and reproducer.

## Why

The dedicated HD256 kernels used the packed `total_q` / `total_k` extents to size each batch's grid. For a packed input with `B` equal-length sequences this launches approximately `B` times more M tiles than necessary, with most CTAs exiting after reading `cu_seqlens`.

After fixing the grid, packed-varlen epilogues become visible in short-sequence profiles:

- Forward used `domain_offset` for the runtime packed-row offset, which discarded the alignment proof needed by `autovec_copy`.
- Backward constructed a dQ TMA destination only for fixed-length inputs. Every varlen dQ tile therefore used the predicate global-store path, including complete tiles that cannot cross a seq
